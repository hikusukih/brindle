**P4.12** Runs gain a goal scope and a schedule trigger; the server builds the scheduler with hooks that create a goal-scoped run from a fire's task prompt and report a goal as busy while it has a run going, and starts the poll and `recover()` at startup, reading cron in the user's time zone from P4.22. Scheduled runs get the 12-hour approval timeout, ending as "approval not given". The tool `propose_schedule` (P4.5) finds the goal from a channel id; a goal-scoped run has a goal id as its scope, so this box makes the tool accept both, or a scheduled run that proposes a schedule is refused as "not a goal's channel".
