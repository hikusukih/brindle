**P6.10** `use_credential`: the built-in tool through which a run makes a credentialed request, as `docs/architecture.md` lists it. Its arguments are a method, a URL and headers and a body whose values may hold `{{secret:name}}` handles; it is `external`, so each call waits for the user's approval unless a standing permission covers it, and the approval card shows the request with handles as names, never values. The tool holds no value: it hands the request to the vault's `credentials.fetch` capability (P6.3), which checks scope, refuses a handle in the URL, path or query, substitutes the value, sends it, scrubs the response and audits it. The result goes through the usual sizing. `web_fetch` stays GET-only with no headers and no handles, so it stays `read`. With tests that an approved call to an in-scope host succeeds against a fake server, that a decline sends nothing, and that the tool's context carries only the capability. _needs P6.3, P2.3_
